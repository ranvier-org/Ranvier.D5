# 3D and Multi-Dimensional Visualization Prior Art for `Ranvier.D5.Wgpu`

This document surveys primary documentation and foundational visualization literature across modern GPU-accelerated 3D plotting and scientific visualization systems to inform the architecture of **`Ranvier.D5.Wgpu`**—pairing [`Ranvier.D5`](../README.md) scales, palettes, statistics, and topology kernels with [`Ranvier.Wgpu`](../../Ranvier.Wgpu/src/Ranvier.Wgpu/README.md), [`Ranvier.Wgpu.Sdl`](../../Ranvier.Wgpu/README.md), and [`Fable.Ranvier.Wgpu`](../../Ranvier.Wgpu/src/Fable.Ranvier.Wgpu/README.md).

Following repository figure-attribution rules (`AGENTS.md`, "Label every figure"), every numeric figure in this survey carries one of three explicit labels: **measured here**, **from documentation** (naming the file or URL), or **general knowledge** (not checked).

## 1. Primary-Source System Survey

### 1.1 Makie.jl (`GLMakie` / `WGLMakie`)

Makie separates 3D coordinate framing (`Axis3`) from retained GPU plot primitives (`Scatter`, `MeshScatter`, `Lines`, `LineSegments`, `Surface`, `Wireframe`, `Band`, `Arrows3D`, `Contour`, `VolumeSlices`, `Volume`, `StreamPlot`, `Voxels`).

#### `Axis3` Coordinate Framing, Aspect, and View-Dependent Silhouette Decoration
Source: [`Axis3` reference (`docs.makie.org/stable/reference/blocks/axis3`)](https://docs.makie.org/stable/reference/blocks/axis3).

- **Camera angles and projection**:
  - `azimuth` defaults to `1.275π` radians (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`), rotating horizontally around the vertical axis from `0` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) on the positive $x$-axis so that $x$ runs rightward and $y$ runs leftward by default.
  - `elevation` defaults to `π/8` radians (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) and is clamped to `[-π/2, +π/2]` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`), establishing a turntable orbit without camera roll.
  - `perspectiveness` defaults to `0.0` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) on a `[0, 1]` scale (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`), where `0.0` is orthographic projection and `1.0` is strong perspective. Makie's reference explicitly recommends avoiding perspective for quantitative reading because foreshortening distorts visual comparisons (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
  - `near` defaults to `0.001` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
- **`aspect` modes**:
  - Defaults to `(1.0, 1.0, 2/3)` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
  - Accepts an explicit `3`-tuple (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) of relative axis lengths `(sx, sy, sz)`, `:equal` as shorthand for `(1, 1, 1)` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`), or `:data` to match physical axis lengths proportionally to data-limit spans so a unit cube in data space renders as a geometric cube (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
- **`viewmode` and layout `protrusions`**:
  - `viewmode` defaults to `:fitzoom` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`), scaling dynamically until the closest cuboid corner touches the layout cell (which causes apparent size "pumping" under rotation). `:fit` inscribes a tight bounding sphere around the cuboid so apparent scale remains invariant during rotation; `:stretch` fills the cell without preserving `aspect`; `:free` behaves like `:fit` while letting zoom/pan move the entire axis without cuboid clipping (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
  - `protrusions` reserves margin space outside the projected cuboid for tick labels and axis titles, defaulting to `30` logical pixels (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) on all `4` sides (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) or a `(left, right, bottom, top)` tuple. `Axis3` intentionally keeps `protrusions` manual rather than reactive to label bounds because cuboid rotation changes projected bounds, which would resize the layout cell and trigger an infinite layout feedback loop (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
- **Automatic back-panel grids and outer silhouette spine selection**:
  - Of the `6` cuboid faces (**general knowledge**: not checked), `Axis3` renders only the `3` camera-backfacing coordinate walls (**general knowledge**: not checked) controlled by `xypanelvisible`, `xzpanelvisible`, and `yzpanelvisible` (all defaulting to `true`, with `xypanelcolor`/`xzpanelcolor`/`yzpanelcolor` defaulting to `:transparent` and `xgridcolor`/`ygridcolor`/`zgridcolor` defaulting to `RGBAf(0, 0, 0, 0.12)` at width `1`; **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
  - For each axis ($x, y, z$), Makie tracks up to `4` cuboid edges (`xspinecolor_1` through `xspinecolor_4`; **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`): spine `1` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) is dynamically bound to the outer silhouette edge where ticks (`xticksize` default `6`, `xticklabelpad` default `5` for $x/y$ and `10` for $z$) and labels (`xlabeloffset` default `40` for $x/y$ and `50` for $z$) are placed (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`), spine `2` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) lies at the interior back-wall corner, spine `3` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) lies opposite the ticks, and spine `4` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) closes the front of the box only when `front_spines = true` (default `false`; **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
  - Plot geometry is clipped to the axis cuboid by default (`clip = true`), overridable per plot via `clip_planes = Plane3f[]` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
- **Predefined 3D interactions**:
  - `:dragrotate` (`DragRotate`, left-drag), `:scrollzoom` (`ScrollZoom`, wheel with `zoommode = :center | :cursor` and single-axis or planar locks via holding `x`, `y`, or `z` keys), `:translation` (`DragPan`, right-drag with `x`/`y`/`z` axis/plane constraints), `:limitreset` (`Ctrl + Left Click` for limits, `Shift + Left Click` for rotation, `Ctrl + Shift + Left Click` for `autolimits!`), and `:cursorfocus` (`FocusOnCursor`, `Alt + Left Click` to re-center on hovered surface/marker) (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).

#### Core 3D Plotting Primitives
- **[`surface`](https://docs.makie.org/stable/reference/plots/surface) and [`wireframe`](https://docs.makie.org/stable/reference/plots/wireframe)**: `surface(x, y, z)` renders a shaded continuous heightfield or curvilinear grid where `x` and `y` can be `1`D coordinate vectors or `2`D coordinate matrices matching `z` (**from documentation**: `docs.makie.org/stable/reference/plots/surface`); `wireframe` extracts and draws the skeletal grid edges of surfaces or `GeometryBasics` meshes (**from documentation**: `docs.makie.org/stable/reference/plots/wireframe`).
- **[`scatter`](https://docs.makie.org/stable/reference/plots/scatter) vs. [`meshscatter`](https://docs.makie.org/stable/reference/plots/meshscatter)**:
  - `scatter` draws camera-facing 2D billboard markers (SDF/sprite shapes in `:pixel` or `:data` `markerspace`; **from documentation**: `docs.makie.org/stable/reference/plots/scatter`).
  - `meshscatter` hardware-instances an arbitrary 3D `marker` mesh (defaulting to a sphere, or e.g. `Rect3f` for 3D bars/glyphs) with per-instance `markersize` accepting either scalar `Real` or anisotropic `Vec3f(sx, sy, sz)` scaling, and per-instance `rotation` accepting `Real` (radians around $z$), `Vec3f` (aligning local $+z$ to the vector), or `Quaternion` (full 3-DOF orientation) (**from documentation**: `docs.makie.org/stable/reference/plots/meshscatter`).
- **[`lines`](https://docs.makie.org/stable/reference/plots/lines), [`linesegments`](https://docs.makie.org/stable/reference/plots/linesegments), and [`band`](https://docs.makie.org/stable/reference/plots/band)**:
  - `lines` renders connected polylines in 3D (`NaN` coordinates break segments), while `linesegments` renders disconnected endpoint pairs `(2k-1, 2k)` (**from documentation**: `docs.makie.org/stable/reference/plots/lines`, `docs.makie.org/stable/reference/plots/linesegments`).
  - `band(lower, upper)` accepts two vectors of `Point3f` (`3`D points; **from documentation**: `docs.makie.org/stable/reference/plots/band`) to form a `3`D ruled surface / ribbon for confidence intervals, extruded trajectories, or waterfall curtains (**from documentation**: `docs.makie.org/stable/reference/plots/band`).
- **[`arrows` / `arrows3d`](https://docs.makie.org/stable/reference/plots/arrows) and [`streamplot`](https://docs.makie.org/stable/reference/plots/streamplot)**:
  - Makie splits quiver plots into `arrows2d` (`Arrows2D`) and `arrows3d` (`Arrows3D`), taking `points` and `directions` (or endpoints via `argmode = :endpoint`, or a field function `f(Point3f)`), decomposing each `3`D arrow into `3` mesh parts (`tail`, `shaft`, `tip`; **from documentation**: `docs.makie.org/stable/reference/plots/arrows`) with `lengthscale`, `normalize`, and `align = :tail | :center | :head` (**from documentation**: `docs.makie.org/stable/reference/plots/arrows`).
  - `streamplot(f, xlimits, ylimits, zlimits)` integrates continuous `3`D vector fields into streamline polylines plus directional arrow markers colored by local vector magnitude (**from documentation**: `docs.makie.org/stable/reference/plots/streamplot`).
- **[`contour`](https://docs.makie.org/stable/reference/plots/contour), [`volumeslices`](https://docs.makie.org/stable/reference/plots/volumeslices), [`volume`](https://docs.makie.org/stable/reference/plots/volume), and [`voxels`](https://docs.makie.org/stable/reference/plots/voxels)**:
  - `contour(x, y, z, vol)` on a `3`D array renders multi-level translucent isosurfaces (**from documentation**: `docs.makie.org/stable/reference/plots/contour`).
  - `volumeslices(x, y, z, vol)` mounts `3` orthogonal `heatmap` planes (`yz`, `xz`, `xy`; **from documentation**: `docs.makie.org/stable/reference/plots/volumeslices`) inside the volume for interactive cross-section inspection.
  - `volume(x, y, z, vol; algorithm = ...)` performs GPU volume ray-casting supporting `6` algorithms (**from documentation**: `docs.makie.org/stable/reference/plots/volume`): `:mip` (maximum intensity projection), `:iso` (isosurface ray-hit with `isovalue` and `isorange`), `:absorption`, `:absorptionrgba`, `:additive`, and `:indexedabsorption` (**from documentation**: `docs.makie.org/stable/reference/plots/volume`).
  - `voxels(x, y, z, chunk)` renders dense `3`D discrete/categorical arrays (`UInt8` IDs mapped to color scales, with `0x00` representing air/empty) by culling hidden interior faces between adjacent occupied voxels (**from documentation**: `docs.makie.org/stable/reference/plots/voxels`).

#### Extra-Dimension Scalar Color Encodings
Source: [Colors explanation (`docs.makie.org/stable/explanations/colors`)](https://docs.makie.org/stable/explanations/colors) and [`surface` reference (`docs.makie.org/stable/reference/plots/surface`)](https://docs.makie.org/stable/reference/plots/surface).

- Every numeric mark accepts `color` (scalar value, `1`D vector, or `2`D/`3`D array), `colormap`, `colorscale` (domain transform function such as `log10`), `colorrange = (cmin, cmax)`, `lowclip` (out-of-range below `cmin`), `highclip` (out-of-range above `cmax`), and `nan_color` (defaulting to `:transparent`, which hides `NaN` cells/vertices cleanly; **from documentation**: `docs.makie.org/stable/explanations/colors`).
- Crucially, `surface(x, y, z; color = C)` accepts an independent `2`D numeric `Matrix` (or color image) `C` of the same grid shape as `z`, decoupling a `4`th data variable (e.g., temperature or stress) from geometric height `z` (**from documentation**: `docs.makie.org/stable/reference/plots/surface`).

### 1.2 Plotly.js `gl3d`

Plotly's `gl3d` subsystem hosts WebGL-accelerated `3`D traces inside `layout.scene` containers.

#### `layout.scene` Axes, Aspect Modes, Camera, and Drag Modes
Sources: [3D charts overview (`plotly.com/javascript/3d-charts/`)](https://plotly.com/javascript/3d-charts/) and [`layout.scene` reference (`plotly.com/javascript/reference/layout/scene/`)](https://plotly.com/javascript/reference/layout/scene/).

- **Axes and interactive hover spikes**: `scene.xaxis`, `scene.yaxis`, and `scene.zaxis` each configure `range`, `type` (`"linear"`, `"log"`, `"date"`, `"category"`), `showbackground` + `backgroundcolor` (shaded back walls), `showgrid` + `gridcolor`, and `showspikes` (default `true`; **from documentation**: `plotly.com/javascript/reference/layout/scene/`), which draws orthogonal `3`D drop-lines ("spikes") from a hovered datum onto the enclosing axis walls and ticks (**from documentation**: `plotly.com/javascript/reference/layout/scene/`).
- **`aspectmode`**: Enumerated `"auto"` (default), `"cube"`, `"data"`, or `"manual"` (paired with `aspectratio: {x, y, z}`; **from documentation**: `plotly.com/javascript/reference/layout/scene/`). Notably, `"auto"` uses proportional `"data"` scaling unless one axis span exceeds `4` times (**from documentation**: `plotly.com/javascript/reference/layout/scene/`) the other two, in which case it automatically falls back to `"cube"` so extreme aspect ratios do not collapse into unreadable slivers (**from documentation**: `plotly.com/javascript/reference/layout/scene/`).
- **`camera` and `dragmode`**:
  - `scene.camera` specifies `eye` (default `{x: 1.25, y: 1.25, z: 1.25}` in normalized scene coordinates; **from documentation**: `plotly.com/javascript/reference/layout/scene/`), `center` (default `{x: 0, y: 0, z: 0}`; **from documentation**: `plotly.com/javascript/reference/layout/scene/`), `up` (default `{x: 0, y: 0, z: 1}`; **from documentation**: `plotly.com/javascript/reference/layout/scene/`), and `projection.type` (`"perspective"` or `"orthographic"`).
  - `scene.dragmode` selects `"turntable"` (fixed-$z$ vertical orbit), `"orbit"` (unconstrained arcball rotation), `"zoom"`, `"pan"`, or `false` (**from documentation**: `plotly.com/javascript/reference/layout/scene/`).

#### `gl3d` Trace Primitives and Multi-Dimensional Projections
- **[`surface`](https://plotly.com/javascript/reference/surface/)**: Takes a `2`D `z` height matrix (with optional `1`D or `2`D `x`, `y` coordinates for rectilinear or curvilinear grids), `cmin`/`cmax`/`cmid`/`colorscale`, `opacityscale`, and **`surfacecolor`**—an independent `2`D array encoding a `4`th scalar variable onto surface color instead of `z` (**from documentation**: `plotly.com/javascript/reference/surface/`). `contours.x`, `contours.y`, and `contours.z` draw isolines directly on the surface and, via `contours.z.project: {x: true, y: true, z: true}`, project flat contour maps onto the `3` back/floor walls (**from documentation**: `plotly.com/javascript/reference/surface/`).
- **[`scatter3d`](https://plotly.com/javascript/reference/scatter3d/)**: Combines `"markers"`, `"lines"`, and `"text"` modes with per-point `marker.size` (`sizemode: "diameter" | "area"`, `sizeref`), `marker.color` (mapped via `colorscale`), `marker.symbol` (2D SDF/sprite shapes such as `"circle"`, `"square"`, `"diamond"`, `"cross"`, `"x"`), `marker.opacity`, `error_x`/`y`/`z`, and **`projection: {x: {show}, y: {show}, z: {show}}`**, which casts 2D point/line shadows onto the `yz`, `xz`, and `xy` walls to disambiguate `3`D depth (**from documentation**: `plotly.com/javascript/reference/scatter3d/`).
- **[`mesh3d`](https://plotly.com/javascript/reference/mesh3d/)**: Renders unstructured triangle meshes via explicit `0`-based index arrays `i`, `j`, `k` (**from documentation**: `plotly.com/javascript/reference/mesh3d/`), or automatic triangulation/hull construction via `alphahull` (`-1` for Delaunay triangulation, `0` for convex hull, `> 0` for $\alpha$-shape; **from documentation**: `plotly.com/javascript/reference/mesh3d/`). Supports `3` distinct color-binding granularities (**from documentation**: `plotly.com/javascript/reference/mesh3d/`): scalar `intensity` with `intensitymode: "vertex" | "cell"`, explicit per-vertex `vertexcolor`, and explicit per-triangle `facecolor` (**from documentation**: `plotly.com/javascript/reference/mesh3d/`).
- **[`cone`](https://plotly.com/javascript/reference/cone/) and [`streamtube`](https://plotly.com/javascript/reference/streamtube/)**: `6`D vector-field traces (`x, y, z, u, v, w`; **from documentation**: `plotly.com/javascript/reference/cone/`, `plotly.com/javascript/reference/streamtube/`). `cone` instances `3`D cones oriented along `(u, v, w)` with `sizemode: "scaled" | "raw"` (or `"absolute"`), `sizeref`, and `anchor: "tip" | "tail" | "cm" | "center"`, coloring by vector norm $\|(u, v, w)\|$ (**from documentation**: `plotly.com/javascript/reference/cone/`). `streamtube` integrates streamlines from `starts: {x, y, z}` into variable-radius `3`D tubes colored by speed and bounded by `maxdisplayed` (**from documentation**: `plotly.com/javascript/reference/streamtube/`).
- **[`isosurface`](https://plotly.com/javascript/reference/isosurface/) and [`volume`](https://plotly.com/javascript/reference/volume/)**: `4`D scalar-field traces (`x, y, z, value`; **from documentation**: `plotly.com/javascript/reference/isosurface/`, `plotly.com/javascript/reference/volume/`) filtered to `[isomin, isomax]` with `surface.count` shells, **`slices.x/y/z`** (`{show, locations}` inserting interior cross-section planes), **`caps.x/y/z`** (sealing clipped volume boundaries so thresholded solids do not look hollow), and `spaceframe` wireframe cells (**from documentation**: `plotly.com/javascript/reference/isosurface/`, `plotly.com/javascript/reference/volume/`).

### 1.3 Datoviz and VisPy

#### Datoviz (`datoviz.org` v0.4)
Sources: [Visual Families (`datoviz.org/reference/visual-families/`)](https://datoviz.org/reference/visual-families/), [Architecture (`datoviz.org/explanation/architecture/`)](https://datoviz.org/explanation/architecture/), [Mesh (`datoviz.org/reference/visual-families/mesh/`)](https://datoviz.org/reference/visual-families/mesh/), [Volume (`datoviz.org/reference/visual-families/volume/`)](https://datoviz.org/reference/visual-families/volume/), [Colormaps (`datoviz.org/reference/colormaps/`)](https://datoviz.org/reference/colormaps/), [Sampled Fields (`datoviz.org/how-to/use-sampled-fields/`)](https://datoviz.org/how-to/use-sampled-fields/), and [Pick Items (`datoviz.org/how-to/pick-items/`)](https://datoviz.org/how-to/pick-items/).

- **Dimensional GPU visual taxonomy**: Datoviz organizes GPU batching units into `15` core visual families (**from documentation**: `datoviz.org/reference/visual-families/`) plus `2` composites (`Polygon`, `Graph`; **from documentation**: `datoviz.org/reference/visual-families/`), grouped by intrinsic dimensionality:
  - *`0`D point-like*: `Point` (circular point sprites), `Pixel` (screen-aligned cells), `Marker` (SDF symbolic shapes with stroke/fill/rotation), `Splat` (experimental Gaussian splats) (**from documentation**: `datoviz.org/reference/visual-families/`).
  - *`1`D line-like*: `Segment` (independent endpoint pairs with per-segment styling), `Path` (connected polylines/curves with joins and variable width), `Vector` (arrow/vector-field glyphs), `Primitive` (raw triangle/line batches) (**from documentation**: `datoviz.org/reference/visual-families/`).
  - *`2`D planar*: `Image` (`2`D sampled fields/quads), `Text` (semantic annotations), `Glyph` (low-level font-atlas quads), `Labels` (categorical integer masks) (**from documentation**: `datoviz.org/reference/visual-families/`).
  - *`3`D volumetric/surface*: `Mesh` (indexed/instanced triangle surfaces with lighting and instance transforms), `Sphere` (analytic ray-cast `3`D sphere impostors with true depth and lighting without polygon tessellation), and `Volume` (`3`D `DvzSampledField` ray-marching / MIP / slice rendering) (**from documentation**: `datoviz.org/reference/visual-families/`, `datoviz.org/reference/visual-families/mesh/`, `datoviz.org/reference/visual-families/volume/`).
- **Retained scene-to-GPU packet architecture and buffer updates**:
  - Datoviz enforces a strict `1`-way pipeline (**from documentation**: `datoviz.org/explanation/architecture/`): retained `Scene` $\rightarrow$ `FramePlan` $\rightarrow$ immutable `DvzSceneFrameArtifact` (freezing upload byte spans so user code can mutate the retained scene immediately without racing GPU execution) $\rightarrow$ `DRP2` (`setup`, `update`, `frame` binary packets) $\rightarrow$ native Vulkan (`vklite`) or browser WebGPU (**from documentation**: `datoviz.org/explanation/architecture/`).
  - Visuals act as batching units over C-contiguous `float32`, `uint8`, and `uint32` arrays uploaded via `dvz_visual_set_data()` / `dvz_visual_set_data_many()`, while **partial interval mutations** update only a modified sub-range via `dvz_visual_set_data_range()` (and `dvz_sampled_field_update_region()` for `2`D/`3`D fields) without reallocating or re-uploading unchanged regions (**from documentation**: `datoviz.org/reference/visual-families/`, `datoviz.org/how-to/use-sampled-fields/`).
  - Scalar color attributes (`DVZ_VISUAL_ATTR_FORMAT_SCALAR_F32`) bind to retained `DvzScale` + GPU colormap lookup tables (`> 150` built-in colormaps; **from documentation**: `datoviz.org/reference/colormaps/`), keeping raw `float32` scalars on the GPU rather than baking RGBA bytes on the CPU.
  - **Asynchronous GPU picking vs. field probing**: Datoviz separates *picking* (rendered item/instance/face/primitive IDs queued via `dvz_panel_query_px()` and polled asynchronously via `dvz_scene_poll_query()` without stalling the input callback) from *probing* (reading field values at data coordinates) (**from documentation**: `datoviz.org/how-to/pick-items/`).

#### VisPy (`vispy.org`)
Sources: [`vispy.scene.visuals` API (`vispy.org/api/vispy.scene.visuals.html`)](https://vispy.org/api/vispy.scene.visuals.html) and [`vispy.scene.cameras` API (`vispy.org/api/vispy.scene.cameras.html`)](https://vispy.org/api/vispy.scene.cameras.html).

- **`SceneCanvas` 3D visuals**: `SurfacePlot` (regular/rectilinear `z = f(x, y)` shaded mesh), `Markers` (anti-aliased SDF point symbols), `Line` (hairline GL primitives or triangulated Agg polylines), `Arrow` (line body + instanced head symbols), `Tube` (extruded Frenet-frame polyline), `Mesh` (indexed `vertices`/`faces` with `vertex_colors` or `face_colors` and smooth/flat shading), `Isosurface` (lazy CPU marching-cubes extraction cached inside `Mesh`), `Volume` (`3`D texture ray-casting with `mip`, `translucent`, `additive`, and `iso` modes), plus `XYZAxis` and `GridLines` (**from documentation**: `vispy.org/api/vispy.scene.visuals.html`).
- **Canonical 3D camera triad**:
  - `TurntableCamera`: orbits around `center` keeping a fixed vertical `up` axis via `elevation`, `azimuth`, `roll`, `fov` (`0` for orthographic; **from documentation**: `vispy.org/api/vispy.scene.cameras.html`), and `distance` / `scale_factor` (**from documentation**: `vispy.org/api/vispy.scene.cameras.html`).
  - `ArcballCamera`: quaternion trackball allowing unconstrained `3`-axis rotation without gimbal poles (**from documentation**: `vispy.org/api/vispy.scene.cameras.html`).
  - `FlyCamera`: `6`-DOF (**general knowledge**: not checked) first-person navigation (`WASD` translation + mouse/key pitch/yaw/roll with `auto_roll` damping) for flying inside dense point clouds or volumes (**from documentation**: `vispy.org/api/vispy.scene.cameras.html`).

### 1.4 VTK / PyVista

VTK (exposed Pythonically through PyVista) defines the canonical scientific visualization taxonomy separating **spatial topology** from **point/cell attribute arrays** and **geometry-generating filters**.

#### Canonical 3D Dataset Topologies and `point_data` vs. `cell_data`
Sources: [PyVista Data Model (`docs.pyvista.org/user-guide/data_model.html`)](https://docs.pyvista.org/user-guide/data_model.html), [`ImageData`](https://docs.pyvista.org/api/core/_autosummary/pyvista.imagedata), [`RectilinearGrid`](https://docs.pyvista.org/api/core/_autosummary/pyvista.rectilineargrid), [`StructuredGrid`](https://docs.pyvista.org/api/core/_autosummary/pyvista.structuredgrid), and [`PolyData`](https://docs.pyvista.org/api/core/_autosummary/pyvista.polydata).

| Dataset Type | Geometry Storage | Topology / Connectivity | Primary 3D Use Cases |
| :--- | :--- | :--- | :--- |
| **`ImageData`** | Implicit: `dimensions = (nx, ny, nz)`, `spacing = (dx, dy, dz)`, `origin = (x0, y0, z0)` (`9` scalars total; **general knowledge**: not checked; implicit structure **from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.imagedata`) | Implicit regular `(i, j, k)` voxel/cell indexing | Uniform scalar/vector volumes, CT/MRI, `3`D KDE/density grids |
| **`RectilinearGrid`** | Implicit tensor product of `3` `1`D coordinate arrays `x[nx]`, `y[ny]`, `z[nz]` (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.rectilineargrid`) | Implicit regular `(i, j, k)` axis-aligned brick indexing | Stretched boundary-layer grids, non-uniform bin edges |
| **`StructuredGrid`** | Explicit `3`D point array of `nx * ny * nz` `Vector3` coordinates (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.structuredgrid`) | Implicit regular `(i, j, k)` hexahedral/quad indexing | Curvilinear surfaces (`surface(X, Y, Z)`), cylindrical/spherical/terrain-following grids |
| **`PolyData`** | Explicit `points` array (`N` `Vector3` vertices; **from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.polydata`) | Explicit `verts`, `lines`, `strips`, and `faces` index arrays | Extracted isosurfaces, slices, ribbons, streamlines, Delaunay/Voronoi meshes |

- **`point_data` vs. `cell_data`**: Every dataset holds dictionary-like `point_data` (length `n_points`, linearly interpolated across triangle/cell interiors by GPU varyings) and `cell_data` (length `n_cells`, piecewise-constant across each face/voxel for categorical IDs, histograms, or finite-volume elements), with multiple named scalar, vector (`3`-component), normal, and tensor arrays coexisting on the same topology (**from documentation**: `docs.pyvista.org/user-guide/data_model.html`).

#### Core Scientific Filters
Sources: [`DataSetFilters`](https://docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters), [`warp_by_scalar`](https://docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.warp_by_scalar), [`contour`](https://docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.contour), [`slice`](https://docs.pyvista.org/api/core/_autosummary/pyvista.dataobjectfilters.slice), [`clip`](https://docs.pyvista.org/api/core/_autosummary/pyvista.dataobjectfilters.clip), [`glyph`](https://docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.glyph), and [`streamlines`](https://docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.streamlines).

- **`warp_by_scalar(scalars, factor = 1.0, normal = None)`**: Displaces `2`D planar grids or `3`D surfaces along vertex normals (or a fixed vector) by `factor * scalar`, turning `2`D heatmaps/contours into `3`D relief surfaces while retaining secondary scalar arrays for coloring (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.warp_by_scalar`).
- **`contour(isosurfaces = 10, scalars = ..., method = 'contour' | 'marching_cubes' | 'flying_edges')`**: Extracts `PolyData` isosurfaces (from `3`D volumes) or isolines (from `2`D surfaces), interpolating any remaining `point_data` channels onto the extracted isosurface vertices so an isosurface of field $A$ can be colored by field $B$ (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.contour`).
- **`slice(normal, origin)` and `clip(normal, origin, invert, crinkle)`**: `slice` intersects any `3`D dataset with an implicit plane (with `slice_orthogonal` producing `3` orthogonal planes) to yield a `PolyData` cross-section; `clip` discards half-space geometry (smoothly cutting cells, or keeping whole cells when `crinkle = True`) (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.dataobjectfilters.slice`, `docs.pyvista.org/api/core/_autosummary/pyvista.dataobjectfilters.clip`).
- **`glyph(orient = True, scale = True, factor = 1.0, geom = ...)`**: Places a unit `PolyData` glyph (`geom`, e.g. arrow, cone, sphere, box) at dataset points (with optional spatial `tolerance` subsampling), orienting by a `3`D vector array and scaling by either vector magnitude or an independent scalar array (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.glyph`).
- **`streamlines(vectors, source_center, source_radius, n_points = 100, ...)`**: Integrates vector fields from spherical or line seed sources (`pointa`, `pointb`) into `PolyData` polylines carrying local velocity/vorticity scalars, commonly piped into a tube filter (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.datasetfilters.streamlines`).

### 1.6 Perceptual and Visualization Research Foundations

Sources: Tamara Munzner, *Visualization Analysis and Design* (A K Peters / CRC Press, `2014`, **from documentation**: [`cs.ubc.ca/~tmm/vadbook/`](https://www.cs.ubc.ca/~tmm/vadbook/); Chapter `5` lecture slides [`VAD-marks.pdf`](https://www.cs.ubc.ca/~tmm/talks/vad/VAD-marks.pdf) and Chapter `6` lecture slides [`VAD-rules.pdf`](https://www.cs.ubc.ca/~tmm/talks/vad/VAD-rules.pdf), **from documentation**: `cs.ubc.ca/~tmm/vadbook/`).

- **Why 3D spatial position is perceptually asymmetric ("No Unjustified 3D")**:
  - Planar `2`D position (`x`, `y` on the image plane) is the highest-accuracy quantitative magnitude channel ("The Power of the Plane"), whereas `3`D depth along the viewing ray ranks markedly lower (**from documentation**: `VAD-marks.pdf`, `VAD-rules.pdf`; in Stevens' psychophysical power law $S = I^n$, apparent planar length has exponent $n \approx 1.0$ whereas depth in pictorial scenes degrades to $n \approx 0.67$, **general knowledge**: not checked).
  - Unjustified `3`D (such as extruded `3`D bar charts of abstract `2`D tables or `3`D pie charts) introduces `3` compounding failure modes (**from documentation**: `VAD-rules.pdf`):
    1. **Line-of-sight occlusion**: foreground marks hide background marks and valleys behind peaks (**from documentation**: `VAD-rules.pdf`).
    2. **Perspective foreshortening**: perspective projection shrinks distant marks and compresses tilted segments, corrupting `1`D length and `2`D area comparisons against the back-wall grid (**from documentation**: `VAD-rules.pdf`).
    3. **Tilted text degradation**: `3`D world-tilted typography foreshortens and aliases against screen pixel grids compared to screen-aligned `2`D typography (**from documentation**: `VAD-rules.pdf`).
  - `3`D is **justified** when the data has intrinsic `3`D spatial or geometric structure (e.g., physical fields, terrain/surfaces with shape topology, trajectories, molecular/CAD/anatomical meshes) or when interactive navigation/slicing resolves occlusion (**from documentation**: `VAD-rules.pdf`).
- **Evidence-backed mitigations for depth ambiguity and occlusion**:
  1. **Orthographic default for quantitative charts** (matching Makie's `perspectiveness = 0.0`; **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) so parallel grid lines remain parallel and identical data heights subtend identical pixel lengths regardless of depth.
  2. **Back-facing cuboid grid planes + silhouette-edge ticks + screen-aligned labels**: drawing grids only on the `3` back-facing cuboid faces (**general knowledge**: not checked; panel flags **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) prevents front-grid occlusion while giving a reference frame, and placing ticks/labels on the outer silhouette edges in crisp 2D screen space preserves legibility at every azimuth/elevation.
  3. **Drop lines, wall shadow projections, and hover spikes** (matching Plotly's `scatter3d.projection`, `surface.contours.project`, and `scene.xaxis.showspikes`; **from documentation**: `plotly.com/javascript/reference/scatter3d/`, `plotly.com/javascript/reference/surface/`, `plotly.com/javascript/reference/layout/scene/`) anchor floating `3`D marks directly to `2`D planar scales on the enclosing walls.
  4. **Section cuts and planar slicing** (Munzner's slicing/cutting view-manipulation idiom; **from documentation**: `VAD-rules.pdf`) convert occluded `3`D interiors into high-precision `2`D planar views.
  5. **Interactive turntable motion parallax**: kinetic depth cues during smooth user-driven turntable rotation rapidly disambiguate relative depth while preserving "up" orientation (`z`-up or `y`-up) so spatial mental maps do not tumble.
- **Retinal channels for `4`th–`7`th+ data dimensions on 3D marks**:
  - **Channel `4` — Color (`luminance` + `chroma`/`hue`)**: Highest-utility continuous (`luminance`/sequential/diverging) or categorical (`hue`) non-positional channel (**from documentation**: `VAD-marks.pdf`). *Critical 3D caveat*: Lambertian/hemisphere surface lighting modulates pixel luminance via surface normal $\mathbf{n} \cdot \mathbf{l}$, which **interferes integrally** with luminance-encoded colormaps (**from documentation**: `VAD-marks.pdf`, `VAD-rules.pdf`). Data-colored marks and surfaces therefore need either unlit mode (`InstanceFlags.Unlit`; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`) or controlled low-contrast shading plus isoline contours.
  - **Channel `5` — Size (`1`D length / `2`D disc radius / anisotropic `3`D glyph scale)**: `1`D length (e.g., column height or arrow shaft length) is judged far more accurately than `2`D area or isotropic `3`D volume (**from documentation**: `VAD-marks.pdf`); encoding `2` independent metrics onto glyph length vs. glyph cross-sectional radius (`Vec3` anisotropic scale) outperforms isotropic sphere volume.
  - **Channel `6` — 3D Orientation (`tilt` / direction vector / quaternion)**: Encodes `2` angular degrees of freedom (unit vector $(\theta, \phi)$) or `3` rotational degrees of freedom (quaternion principal axes) on asymmetric glyphs such as cones, arrows, or ellipsoids (**from documentation**: `VAD-marks.pdf`).
  - **Channel `7` — Shape (`marker` symbol / unit `MeshData`)**: Identity channel strictly for categorical/nominal attributes with small cardinality (typically $\le 6\text{–}8$ distinct `3`D shapes; **general knowledge**: not checked; categorical role **from documentation**: `VAD-marks.pdf`).
  - **Channel `8` — Opacity ($\alpha$)**: Useful for de-emphasizing context/unselected context (`focus + context`) or multi-shell isosurfaces, but carries low quantitative precision (`2–3` discriminable levels; **general knowledge**: not checked) and requires depth-sorting or order-independent strategies on the GPU.

## 3. Distilled Taxonomy of Essential Primitives for `Ranvier.D5.Wgpu`

Before proposing new abstractions, we align against what already exists in [`Ranvier.D5`](../src/Ranvier.D5/Ranvier.D5.fsproj) (`Scale`, `TimeTicks`, `Format`, `Chromatic`, `Contour`, `Delaunay`, `Reactive`) and [`Ranvier.Wgpu`](../../Ranvier.Wgpu/src/Ranvier.Wgpu/README.md) (`WgpuContext`, `ScenePass`, `Camera3D`, `MeshData`/`MeshHandle`/`MeshBuilder`, `InstanceBatch` [`96` bytes/instance; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`], `LineBatch` [`32` bytes/endpoint; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`], `DiscBatch` [`64` bytes/disc; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`], `SectionPlane`, `Shaders.composeScene`, `SetUserUniforms` [`16` `vec4<f32>` = `256` bytes; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/README.md`], and `1×1` `RGBA32Uint` `WgpuContext.pick` / browser `PickAsync` [**from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/WgpuContext.fs`, `Fable.Ranvier.Wgpu/README.md`]).

Crucially, `Ranvier.Wgpu` currently enforces **no texture/sampler/storage bindings** (`2` uniform blocks + vertex/instance buffers only; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/README.md`) and composites `4×` MSAA `WgpuSdlSurface` directly underneath HTML, CSS, and `Ranvier.D5` SVG with `0.00 ms` readback (**from documentation**: `Ranvier.Wgpu/README.md`). That shapes every design choice below.

### (a) 3D Coordinate Space, Aspect Modes, and View-Dependent Axis/Grid/Tick Framing

1. **Decoupled `Scale3D` + `BoxAspect` transform (`Data -> World`)**:
   - Pair `3` immutable `Ranvier.D5` scales (`x`, `y`, `z`: `Continuous`, `Piecewise`, `TimeScale`, or categorical `Band<'Key>`; **from documentation**: `Ranvier.D5/src/Ranvier.D5/Scale.fs`) mapping domain intervals into normalized box coordinates `[-0.5, +0.5]` (or `[0.0, 1.0]`) multiplied by a physical world box `(boxX, boxY, boxZ)` (combining ECharts `grid3D`'s `boxWidth`/`boxHeight`/`boxDepth` with Makie/Plotly aspect modes; **from documentation**: `echarts.apache.org/en/option-gl.html`, `docs.makie.org/stable/reference/blocks/axis3`, `plotly.com/javascript/reference/layout/scene/`):
     - `BoxAspect.Cube` (`1 : 1 : 1`, or `(1.0, 1.0, 2/3)` chart default per Makie `Axis3`; **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
     - `BoxAspect.Data` (world extents proportional to domain spans, with Plotly's `4×` auto-guard option so degenerate ratios do not collapse; **from documentation**: `plotly.com/javascript/reference/layout/scene/`).
     - `BoxAspect.Manual(wx, wy, wz)` for explicit physical proportions.
   - Support axis reversal (`xReversed`, `yReversed`, `zReversed`; **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`) via descending `Scale` ranges, which `Ranvier.D5.Scale` already supports natively (**from documentation**: `Ranvier.D5/docs/design.md`).
2. **View-dependent back-panel grid and outer silhouette tick selection**:
   - From `Camera3D.Position - Camera3D.Target` (or view direction in orthographic mode), classify each of the `6` cuboid faces (**general knowledge**: not checked) per frame by outward face-normal dot product: render background quads (`AlphaBlend` `InstanceBatch` with `InstanceFlags.Unlit | InstanceFlags.IgnoreSectionPlane`) and major/minor tick gridlines (`LineBatch`) **only on the `3` back-facing planes**, matching Makie `Axis3` and Plotly `scene` (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`, `plotly.com/javascript/reference/layout/scene/`).
   - Select the outer silhouette edge for each axis ($x, y, z$) where `1` adjacent cuboid face is front-facing and `1` is back-facing (**general knowledge**: not checked), emitting tick hairlines outward in `LineBatch` and projecting tick anchor coordinates via `Camera3D.projectToScreen` (**from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`) into crisp, screen-aligned `Ranvier.D5` SVG / `Ranvier.View.Dsl` overlay labels with reserved layout `protrusions` (default `30`–`40` px; **from documentation**: `docs.makie.org/stable/reference/blocks/axis3`). This completely avoids `3`D font-atlas texture dependencies in `Ranvier.Wgpu` while delivering razor-sharp, un-foreshortened typography on both native `Ranvier.Wgpu.Sdl` and browser `Fable.Ranvier.Wgpu`!

### (c) Multi-Dimensional Channel Encodings (`4`D–`7`D+)

1. **`4`th dimension — Independent scalar color channel (`surfacecolor` / `color` matrix)**:
   - Every `Surface3D`, `IsoSurface3D`, `PathTube3D`, `ScatterBillboard`, and `Glyph3D` primitive must accept an optional `colorValues` channel independent of `(x, y, z)` geometry, mapped through `Ranvier.D5.Scale` (`linear`, `log`, `power`, `sqrt`, `piecewise`) + `Ranvier.D5.Chromatic` (`sequential`, `diverging`, `cyclic` in `Srgb`, `Lab`, or `Hcl`; **from documentation**: `Ranvier.D5/src/Ranvier.D5/Scale.fs`, `Chromatic.fs`) with explicit `LowClip`, `HighClip`, and `Missing` (`None`/`NaN`: omit geometry vs. fallback `RgbaColor`) policies (**from documentation**: `docs.makie.org/stable/explanations/colors`, `plotly.com/javascript/reference/surface/`).
   - Provide a shading-preservation mode (`Unlit` or reduced normal-lighting contrast + surface contour lines) so `3`D directional lighting does not corrupt perceptual `Lab`/`Hcl` luminance scales (**from documentation**: `VAD-marks.pdf`, `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`).
2. **`5`th & `6`th dimensions — Anisotropic `Vector3` scale and `Quaternion` / direction-vector orientation**:
   - `Instance3D` already packs a full `4×4` world matrix (`ModelCol0..ModelCol3`; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`), enabling simultaneous `3`D position (`x, y, z`), `3`D vector orientation (aligning unit cone/arrow/cylinder $+Y$ axis to `(u, v, w)` or full `Quaternion`), and anisotropic `Vector3(radiusX, lengthY, radiusZ)` scaling (`5`–`9` quantitative dimensions in `1` `InstanceBatch`; **from documentation**: `docs.makie.org/stable/reference/plots/meshscatter`, `deck.gl/docs/api-reference/mesh-layers/simple-mesh-layer`).
   - On `DiscBatch`, `DiscInstance3D` natively encodes `2` extra quantitative `[0, 1]` ring-progress channels (`verifiedFrac`, `inProgressFrac`) plus `portalHollow` around each `3`D point (**from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`)—a built-in multi-variate radial glyph unique to `Ranvier.Wgpu`.
3. **Depth-anchoring projections, wall contours, and live `SectionPlane` cuts**:
   - **Wall projections (`Projection.XY | XZ | YZ`)**: Project `3`D scatter points (`DiscBatch` or flat `InstanceBatch`), `3`D trajectories (`LineBatch`), or `2`D `Ranvier.D5.Contour.compute` isolines (`LineBatch`) onto the active back/floor planes (**from documentation**: `plotly.com/javascript/reference/scatter3d/`, `plotly.com/javascript/reference/surface/`, `Ranvier.D5/docs/contours.md`).
   - **Live GPU section clipping**: `ScenePass.withSection (SectionPlane.create normal offset)` clips all `InstanceBatch` geometry in WGSL at `0` CPU mesh-rebuilding cost while highlighting the exact cross-section intersection band via `LightingRig.SectionContourColor` and `SectionContourWidth`, while axis frames/grids carry `InstanceFlags.IgnoreSectionPlane` so the reference box remains intact (**from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Types.fs`).

### (d) Interaction and Camera Models

1. **Unified Turntable + Orthographic/Perspective `ChartCamera3D`**:
   - Default quantitative `3`D charts to **turntable orbit** (`azimuth`, `elevation` clamped away from poles, fixed `Up` axis) so vertical/horizontal axes keep a stable perceptual "up", with optional `Arcball` quaternion mode for free `3`D molecular/mesh inspection (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`, `vispy.org/api/vispy.scene.cameras.html`, `plotly.com/javascript/reference/layout/scene/`).
   - Add a `perspectiveness` parameter in `[0, 1]` (or an orthographic projection builder alongside `Camera3D.projMatrix` in `Ranvier.Wgpu` / `Ranvier.D5.Wgpu`), paired with Makie's `:fit` bounding-sphere framing so rotating an `Axis3` cuboid never "pumps" its apparent scale or clips corners (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
   - Support modifier-key single-axis / single-plane zoom and pan (`X`, `Y`, `Z` domain re-ranging through Ranvier signals) plus `Alt + Click` focus-on-point and reset-view shortcuts (**from documentation**: `docs.makie.org/stable/reference/blocks/axis3`).
2. **Hardware `1×1` GPU picking + `Scale.invert` hover spikes**:
   - `WgpuContext.pick` (and `PickAsync` in `Fable.Ranvier.Wgpu`) already executes a `1×1`-scissor `RGBA32Uint` render pass returning both `PickId: uint32` and exact `WorldPosition: Vector3` (`16` bytes mapped; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/WgpuContext.fs`).
   - Encoding `(seriesId, datumIndex)` into the non-zero `32`-bit `PickId` (**general knowledge**: not checked; `PickId = 0u` is empty background **from documentation**: `WgpuContext.fs`) identifies exact marks for `ScatterBillboard` (`DiscBatch`) and `Glyph3D` (`InstanceBatch`), while `WorldPosition` mapped backward through `Ranvier.D5.Scale.invert` (**from documentation**: `Ranvier.D5/src/Ranvier.D5/Scale.fs`) gives **continuous `3`D surface/isosurface coordinate probing** (`(x, y, z, value)`) AND drives `3` orthogonal hover "spike" lines in a lightweight dynamic `LineBatch` onto the axis walls (**from documentation**: `plotly.com/javascript/reference/layout/scene/`, `echarts.apache.org/en/option-gl.html`)!

### (e) GPU Optimization Patterns Distilled from Prior Art

1. **Split / dirty-tracked channel computation (`updateTriggers` via Ranvier `Memo`s)**:
   - Following Deck.gl's `AttributeManager` + `updateTriggers` (**from documentation**: `deck.gl/docs/developer-guide/performance`, `deck.gl/docs/api-reference/core/attribute-manager`), keep data-channel arrays (`positions: Vector3[]`, `scales: Vector3[]`, `rotations: Quaternion[]`, `scalars: float32[]` / `colors: RgbaColor[]`) in separate `Ranvier` memos/signals rather than recomputing geometry from scratch when only a palette or color range changes. Re-pack the `96`-byte `Instance3D[]` span (`InstanceBatch.UpdateInstances(ReadOnlySpan<Instance3D>)`; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/Batches.fs`) from cached position/transform arrays when only `color` updates, avoiding `Scale` or triangulation work on unchanged channels.
2. **Topology index-buffer reuse on deforming grids (`StructuredGrid` / live surfaces)**:
   - As `AGENTS.md` emphasizes ("Models are live by default... a simulation advances continuously"), a live `(nx, ny)` surface whose heights `z(t)` or colors `c(t)` evolve at `60` Hz has invariant grid connectivity (`Indices: uint32[]` of length `(nx - 1) * (ny - 1) * 6`; **general knowledge**: not checked) as long as the missing-data mask does not change (**from documentation**: `docs.pyvista.org/api/core/_autosummary/pyvista.structuredgrid`). Caching the topology index array (and updating only vertex positions/normals/colors, or adding a `MeshHandle.UpdateVertices(ReadOnlySpan<Vertex3D>)` fast path using `wgpuQueueWriteBuffer` if needed) eliminates index-buffer reallocation and GC churn on every simulation tick.
3. **GPU colormap LUT in `Shaders.UserUniformSlots` vs. CPU per-vertex color**:
   - `Ranvier.Wgpu` provides `16` `vec4<f32>` user uniform slots (`256` bytes total; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/README.md`) accessible via `Shaders.composeScene` hooks (`Declarations`, `Varyings`, `VertexEnd`, `FragmentLit`) without any texture binding (**from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/README.md`).
   - Passing a scalar `t` in `Vertex3D.Color.x` (or `Instance3D.ColorRoughness.x`), `[cmin, cmax, lowClipFlag, highClipFlag]` in `user.slots[0]`, `nanColor` / clip colors in `user.slots[1..2]`, and a `9`–`11` stop piecewise palette (such as `Chromatic.blues` with `9` stops or `Chromatic.redBlue` with `11` stops; **from documentation**: `Ranvier.D5/src/Ranvier.D5/Chromatic.fs`) in `user.slots[3..13]` allows **zero-upload interactive `colorrange` dragging, thresholding, and palette switching** purely by writing `256` uniform bytes (`WgpuContext.SetUserUniforms`)—matching Datoviz's `DvzScale` GPU scalar-mapping speed while staying `100%` within `Ranvier.Wgpu`'s texture-free contract! When exact perceptual `Lab`/`Hcl` interpolation (`Ranvier.Anime.ColorSpace`; **from documentation**: `Ranvier.D5/docs/chromatic.md`) is requested, bake `16`–`13` uniform stops in `Lab`/`Hcl` on the CPU or evaluate per-vertex `Vertex3D.Color` when the palette changes.
4. **Instancing vs. merged indexed meshes**:
   - Follow Datoviz's batching rule ("Prefer one visual with many items over many visuals with one item each"; **from documentation**: `datoviz.org/reference/visual-families/`): use `DiscBatch` (`64` bytes/mark; **from documentation**: `Types.fs`) for $\ge 10^4$–$10^6$ (**general knowledge**: not checked) `0`D points, `InstanceBatch` (`96` bytes/mark; **from documentation**: `Types.fs`) for repeated `3`D glyphs (`bar3D`, `cone`, `arrows3d`, `meshscatter`), and a single merged `MeshHandle` (`40` bytes/vertex; **from documentation**: `Types.fs`) for connected continuous topology (`Surface3D`, `IsoSurface3D`, `Band3D`, `StreamTube3D`, `VolumeSlices3D`).
5. **Throttled / on-demand `1×1` scissor GPU picking**:
   - Unlike Deck.gl's full-viewport `24`-bit color picking buffer (**from documentation**: `deck.gl/docs/developer-guide/custom-layers/picking`), `Ranvier.Wgpu`'s `WgpuContext.pick` clips rasterization to a `1×1` scissor rectangle and copies only `1` texel (`16` bytes into a `256`-byte row-aligned readback buffer; **from documentation**: `Ranvier.Wgpu/src/Ranvier.Wgpu/WgpuContext.fs`). On native `WgpuContext.Pick` (synchronous `wgpuBufferMapAsync` + `wgpuDevicePoll`) and browser `PickAsync` (asynchronous promise; **from documentation**: `Fable.Ranvier.Wgpu/README.md`), trigger picking only on pointer-move/click events when the pointer has moved (and coalesce to at most `1` in-flight `PickAsync` in the browser, matching Datoviz's non-blocking query polling pattern; **from documentation**: `datoviz.org/how-to/pick-items/`).
